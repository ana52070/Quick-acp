## 一、更新摘要与根因定位

在 0.1.6 版本中，虽然加入了默认本机路由保护与错误设备工具拦截机制，但在长任务执行场景下暴露了底层连接与错误码映射缺陷：

### 1. 心跳看门狗 75 秒本地误杀
- **故障机制**：AWS Quick 网关在持续进行长文本或多轮工具调用的业务数据流传输时，可能不会单独下发 WebSocket 控制层 `pong` 帧。原心跳看门狗仅认可控制层 `pong` 判定活跃，忽略了持续的高频业务数据帧入站。
- **直接后果**：长任务在运行至约 75 秒左右（实测约 77 秒）时，本地看门狗判定心跳超时，主动触发 `4002/ping_timeout` 关闭套接字，造成任务非预期中断。
- **修复措施**：修改看门狗逻辑，增加“业务入站保活机制”（只要有业务帧持续入站即重置保活状态），同时细化无任何响应与有 pong 无业务的区别判定。

### 2. 套接字异常误报认证错误（假性 `child_auth_required`）
- **故障机制**：在 `src/acp/agent.ts` 中，普通套接字异常（如底层被断开后发送触发的 `socket is not open`）以及路由拦截异常被错误地包装为 `RequestError(-32000, ...)`。而在 ACP 官方 SDK 规范中，`-32000` 属于专属的 `RequestError.authRequired()` 认证错误码。
- **直接后果**：Codeg 客户端底层依赖 Rust 的 `ErrorCode::AuthRequired` 进行解析，导致在连接中断或常规错误时，界面直接弹窗提示“child_auth_required / 需要登录重新认证”，严重误导用户定位问题。
- **修复措施**：将普通网络套接字错误与设备路由拦截错误统一纠正为标准内部错误码 `-32603`（InternalError），彻底消除假性认证弹窗。

### 3. 连接生命周期管理与竞争隔离
- **故障机制**：看门狗主动关闭连接时未向会话层发出非正常关闭通知，导致 `connected` 标记残留为 true；旧套接字连接上的迟到 `close` 事件容易在快速重连时误清理新建立连接的看门狗。
- **修复措施**：补齐看门狗主动关闭时的非正常关闭通知，解绑失效监听，增加连接唯一身份标记以实现旧连接迟到 `close` 事件的竞争隔离。

### 4. 异常助手工具审计轨迹落盘
- **修复措施**：完善异常路径处理，确保当会话发生异常或异常终止时，助手工具调用卡片与审计轨迹正常保存到磁盘持久化目录，保留异常路径的已执行工具记录。

## 四、客户端配置示例与版本固定

在 Codeg 中添加自定义代理配置时，推荐直接指定 `quick-acp@0.1.7`：

```json
{
  "npx": {
    "package": "quick-acp@0.1.7",
    "args": []
  }
}
```

或 command/args 配置：
```json
{
  "command": "npx",
  "args": ["-y", "quick-acp@0.1.7"],
  "env": {
    "QUICK_ACP_ALLOW_SHELL": "1"
  }
}
```

> **边界提示**：
> 0.1.7 发布后，默认提示即可直接完成常规本机开发任务，无需像 0.1.5 一样在提示词中附加“限定 quick-tool-call 本机通道”的人工提示词约束。
